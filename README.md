## 4. 계산 엔진에 대해

### 4-1. 자미두수(동양)

- **엔진**: [`iztro`](https://github.com/SylarLong/iztro) 2.6.5 — 자미두수 명반(12궁·14주성·사화·대한·유년)을
  계산하는 오픈소스 라이브러리입니다. 음양력·윤달·시진 보정이 들어 있습니다.
- **음력 입력**: `korean-lunar-calendar` 로 **한국 음력 → 양력** 변환 후 계산합니다(윤달 지원).
  한국 음력은 KST 기준이라 중국 음력과 드물게 하루 어긋날 수 있어, 음력으로 입력한 경우 입력값을
  그대로 표기하고 보정 메모를 남깁니다.
- **용어**: iztro 는 내부 계산을 중국어로 반환합니다. 화면에 중국어가 새지 않도록
  `lib/terms.ts` 에서 12궁·14주성·보좌성·잡성·사화·간지·오행국·밝기·십이신을 100% 한국 통용 표기로
  매핑합니다. (디자인 요소로 쓰인 '命宮' 같은 한자 라벨은 의도된 장식이며, 계산 문자열이 아닙니다.)
- **공궁 처리**: 명궁에 주성이 없으면 전통 기법대로 천이궁(맞은편)의 주성을 빌려 성향을 읽고,
  화면에 "천이궁에서 빌려온 주성"이라고 명시합니다.

### 4-2. 서양 점성술

- **태양 황경**: Meeus 저정밀 공식. **달 황경**: Meeus 47장 축약 급수(오차 0.3° 이내).
- **수성~토성**: JPL 근사 궤도요소(1800–2050) → 케플러 방정식 → 지심 황경. 자리 판정에 충분한 정밀도입니다.
- **어센던트·MC**: 지방 항성시(GMST + 경도)와 황도경사로 계산.
- **하우스**: 어센던트 자리부터 사인 하나씩 나누는 **Whole Sign** 방식입니다(화면에 명시).
- **출생지**: 아직 입력받지 않아 **서울(37.57°N, 126.98°E)** 기준으로 계산하며, 화면·FAQ에 표기합니다.
- **지수**: 금성·달·목성·화성·토성의 하우스와 원소 일치도로 3지수(연애·금전·일)를 계산합니다.
  자미두수 3지수와는 계산 근거가 다르며, 리포트에도 그렇게 적혀 있습니다.

## 5. 시너스트리(서양 점성술 궁합) 퍼널

2순위 추가 기획. **무료 점수 → 핵심 각 2개 → 심층 시너스트리 리포트**로 이어집니다.

- **계산(`lib/synastry.ts`)**: 두 사람의 태양·달·수성·금성·화성·목성·토성 + 어센던트를 점으로 세우고,
  A의 행성 × B의 행성을 모두 맞대어 주요 각(합 0° · 육분 60° · 사분 90° · 삼분 120° · 대립 180°)을 찾습니다.
  행성 쌍마다 무게가 다릅니다(달×달, 금성×화성, 태양×달이 가장 무겁습니다).
- **원소 궁합**: 두 사람의 우세 원소(불·흙·공기·물) 조화도를 계산하고, 달·금성 원소도 축별로 반영합니다.
- **3축 점수**: 감정의 온도 · 끌림의 세기 · 오래 가는 힘. 시너스트리 지수는 세 축의 가중 평균입니다.
  자미두수 3지수(연애·금전·일)와는 별개 축이며, 화면에서는 이 세 축만 씁니다.
- **무료 30%**: 지수와 함께 가장 강한 흐름 1개·가장 강한 마찰 1개(핵심 각 2개)만 공개합니다.
- **상품**: `synastry` — 6,900원(두 테마 공통). 인하우스 디지털 결제 레인(페이앱)을 그대로 씁니다.
  결제 후 `SynastryReport` 화면이 열리고, 프리뷰에서 입력한 상대방 정보가 결제 모달에 그대로 넘어갑니다.
- **진입**: 서양 탭 랜딩 상품 카드 · 서양 무료 결과의 「SYNASTRY」 섹션.

## 6. 2027 정미년(丁未) 신년 부적 · 원석 굿즈 퍼널

1순위 추가 기획. **무료 부적 → 2027 정밀 리포트 → 수호 원석 굿즈**로 한 번에 이어집니다.

- **해의 값(고정)**: 2027년은 **정미년(丁未)** — 丁(음화)이 未(토)에 앉은 **'붉은 양의 해'**입니다.
  (丙午·화마는 2026년입니다.) 화토(火土)의 기운이 한 해를 덮는다는 전제로 문장을 씁니다.
- **사용자 값(계산)**: `chart.year2027` — 엔진에 `horoscope('2027-06-01')`을 넣어 **2027 유년 명궁·유년 사화 4개**와
  2027년 기준 재백·부처·관록 궁을 뽑습니다. 숫자를 지어내지 않습니다.
- **무료 부적**: `renderAmulet2027()` 이 1080×1620 PNG를 그립니다(다크·금박·주성 고유 빛, 띠 그림 없음).
  화면 카드와 저장 이미지가 같은 문구·같은 배열을 씁니다.
- **30% 프리뷰**: 열두 달 중 사화가 앉은 달(열림·추진·평판·정리)과 나머지 달의 문장을 만들고,
  무료 화면에서는 앞 세 달만 공개한 뒤 나머지는 잠급니다.
- **상품**: `newyear2027` — 9,900원(캐릭터 테마 6,900원). 결제는 인하우스 디지털 결제 레인을 그대로 쓰고
  (실청구 없음), 결제 후 `NewYearReport` 화면이 열립니다.
- **굿즈**: 부족한 기운(오행국 × 2027 화토)에 맞춰 원석을 고르고, 팔찌·부적 참·키링 3종을 추천합니다.
  상세 보기 + **출시 전 장바구니**(합계 표시, 결제·배송 없음)로 예약 동선을 미리 검증합니다.
- **진입**: 랜딩 배너(두 테마 모두) · 무료 결과의 「2027 신년 부적」 버튼 · 결과 하단 섹션.

  **지금 열려 있어(무료) / 열면 더 열려(+70%)** 목록을 함께 보여 줍니다. 무료 결과 화면(자미두수 · 서양 · 2027 · 궁합 · 시너스트리)
  다섯 곳이 모두 이 컴포넌트를 씁니다. 블러 티저는 내용을 가리되, **무엇이 열리는지는 목록으로 먼저 보여** 줍니다.
  (스텔로그는 무료로 목차 9장과 첫 장을 열고 "이 책에 이어질 이야기 I~IX"를 전부 보여 준 뒤 구매로 넘깁니다.)
- **해금 버튼 문구 일관성**: `productUnlockCta()` → `{가격}원으로 나머지 70% 열기`. 무료 30%를 본 바로 그 자리에서
  남은 70%를 같은 말로 이어 붙입니다.
- **결제 모달 약속**: "열면 이 세 가지가 먼저 보여요(01·02·03)" + "무료로 본 30%에 이어서, 나머지 70%가 열립니다".
  (스텔로그의 '결과를 열면 이 세 가지가 먼저 보여요' 구조를 상품 포인트 3개로 옮긴 것)
- **하지 않은 것**: ① 마감 카운트다운(`D-44 · 지금 50% 세일` — 스텔로그는 연말에 끝나는 상품에만 씀, 우리 상품은 기한이 없음)
  ② 후기·별점·누적 발행 수(지어낸 사회적 증거는 넣지 않음 — 실제 이용자가 생기면 그때)
  ③ 별조각 같은 재화·멤버십(실결제 연동 단계에서 검토).

## 8. AI 리포트 연결 (다음 단계)

`.env.local` 파일을 만들고 아래를 채우면 프리미엄 리포트 하단의 **[AI로 다시 생성]** 버튼이 살아납니다.

VITE_AI_PROVIDER=gemini      # gemini | openai | claude
VITE_AI_API_KEY=...
VITE_AI_MODEL=gemini-2.0-flash   # 선택

- 프롬프트: `buildPrompt({ tier, chart, partner? })` → `{ system, user }`
- 호출: `generateAiReport(...)` → `{ ok, markdown }` (실패 시 로컬 엔진 결과 유지)
- **운영 배포 시**: `VITE_` 값은 브라우저 번들에 노출됩니다. `services/aiReport.ts` 의
  `callProvider()` 한 함수만 자체 서버 프록시 호출로 바꾸고 API 키는 서버 환경변수로 옮기세요.
  (요금 폭탄·키 유출 방지)

## 9. 결제와 배포

### 9-1. 결제 (페이앱 API + Cloudflare Workers)

- 결제는 **페이앱(PayApp) REST API** 로 처리합니다. 결제 금액은 브라우저가 아니라
  `workers/src/index.ts` 가 상품표(`src/lib/products.ts`)를 그대로 읽어 다시 계산합니다.
- 흐름: 결제 버튼 → `POST /api/payapp/request` → 페이앱 결제창 → `feedbackurl` 웹훅 검증
  (`linkval`·`hash`·`mul_no`·금액·`pay_state=4`) → HMAC-SHA256 해금 토큰 발급·KV 저장 →
  `returnurl` 복귀 후 `GET /api/payapp/status` → `GET /api/payapp/verify` → 리포트 열림.
- `VITE_PAYAPP_WORKER_URL` 이 없으면 미리보기 모드로 동작합니다(결제창 없이 화면 흐름만 확인).
- 배포·가입 순서와 입력값은 **[PAYAPP_SETUP_GUIDE.md](./PAYAPP_SETUP_GUIDE.md)** 에 정리했습니다.

### 9-2. 빌드·배포

| 대상 | 명령 | base |
| --- | --- | --- |
| GitHub Pages (현재 라이브) | `npm run build` → `dist/` 를 `gh-pages` 에 | `/byulgyeol/` |
| Cloudflare Pages (결제용) | `npm run build:pages` (`VITE_BASE_PATH=/ VITE_ENABLE_GOODS_CHECKOUT=false`) | `/` |
| 로컬 확인 | `npm run preview` | `/byulgyeol/` |

`VITE_ENABLE_GOODS_CHECKOUT=false` 는 **1차 결제 심사용** 설정입니다. 2027 수호 원석 굿즈의
장바구니·알림 신청만 숨기고, 2027 무료 운세·무료 부적 카드는 그대로 노출합니다.

### 9-3. 사업자 정보·정책

- 사업자 정보는 `src/config/legal.ts` 한 곳에서 관리하고 `VITE_BIZ_*` 로 덮어쓸 수 있습니다.
- 통신판매업 신고번호는 발급 후 `VITE_BIZ_TELECOM_NO` 에 넣으면 푸터와 정책 문서에 함께 반영됩니다.
- 정책 3종(이용약관·개인정보처리방침·환불/청약철회)은 푸터와 결제 모달에서 바로 열립니다.

### 9-4. 남은 과제

1. **리포트 저장·재열람**: 현재는 메모리 상태만 사용(새로고침 시 사라짐). 해금 토큰은 Worker KV에
   남아 있어 다시 결제하지 않고도 복구할 수 있지만, 리포트 본문 자체의 재열람은 다음 단계 과제입니다.
2. **리포트 저장·재열람**: 현재는 메모리 상태만 사용(새로고침 시 사라짐). Supabase 등에
   `이메일 + 상품 ID + 명반 스냅샷` 형태로 저장하고 매직링크로 재열람하게 하면 CS가 크게 줄어듭니다.
3. **배포**: Vercel / Cloudflare Pages 정적 배포로 충분합니다. 빌드 결과물은 `dist/`.
4. **법적 고지**: 하단에 "의료·법률·투자 판단 근거 아님" 문구를 넣어 두었습니다. 유료 운세 콘텐츠는
   전자상거래법상 청약 철회 제한 고지가 필요하므로 결제 모달 문구를 실제 약관과 맞춰 주세요.
5. **바이럴 루프**: 공유 카드(1080×1350)는 인스타그램·스레드 4:5 규격입니다. 공유 URL에
   `?ref=<명반ID>`를 붙여 유입을 추적하면 광고 없이 성장하는 구조를 만들 수 있습니다.
